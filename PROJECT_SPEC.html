Washing Machine Simulator - Project Specification#

1. Project Goal#

Build a washing machine simulator on STM32F411E-DISCO to learn FreeRTOS through a realistic embedded application.

The project should demonstrate practical usage of:

  • Tasks
  • Queues
  • Event Groups
  • Task Notifications
  • Binary Semaphore
  • Counting Semaphore
  • Mutex
  • Software Timers
  • State Machines
  • SEGGER SystemView

The focus is on understanding RTOS architecture and inter-task communication rather than building a commercial washing machine product.

Start / Confirm Button — (PD2, external)#

GPIO:

PD2

Interface:

EXTI2, falling edge, internal pull-up (button connects PD2 to GND)

Function:

Press:

  • Confirm selection
  • Start selected wash mode

Door Sensor Simulation Button — (PD5, external)#

GPIO:

PD5

Interface:

GPIO Input, pull-up, polled every 100 ms by SensorTask

Function:

Toggle Press:

  • Odd presses: door OPEN → triggers EVT_ERROR
  • Even presses: door CLOSED → normal operation
  • Default state at startup: CLOSED

Water Level Sensor Simulation Button — (PD6, external)#

GPIO:

PD6

Interface:

GPIO Input, pull-up, polled every 100 ms by SensorTask

Function:

Toggle Press:

  • Odd presses: water FULL → machine advances from FILL_WATER to WASHING
  • Even presses: water EMPTY (no immediate action)
  • Default state at startup: EMPTY

7. RTOS Architecture#

Bốn task chia sẻ với nhau qua ba queue và một event group. Mọi luồng dữ liệu đều một chiều và mỗi đối tượng chỉ có một bên gửi, một bên nhận chính.

Ký hiệu Loại Vai trò
🟠 bầu dục ISR Chạy trong ngắt, chỉ ghi vào queue rồi thoát
🔵 hộp chữ nhật Task Vòng lặp vô hạn, phần lớn thời gian ở trạng thái Blocked
🟢 hình trụ Queue Chuyển dữ liệu theo thứ tự (FIFO), sao chép theo giá trị
🟣 hộp đôi Event Group Bộ cờ trạng thái dùng chung, task chờ tổ hợp bit
⚪ lục giác Software Timer Đếm giờ, hết giờ thì set bit EVT_TIMEOUT

Cách đọc:

  1. Luồng lệnh — nút bấm tạo ngắt; ISR đẩy sự kiện vào Button Queue; UI Task đổi tên cử chỉ thành lệnh (CMD_NAVIGATE / CMD_CONFIRM) rồi gửi qua Command Queue. WashingManager mới là bên giữ con trỏ menu và diễn giải lệnh.
  2. Luồng sự kiện — Sensor Task (định kỳ) và các Software Timer (khi hết giờ) set bit vào Event Group; WashingManager chờ đúng những bit có nghĩa ở trạng thái hiện tại.
  3. Luồng hiển thị — WashingManager gửi nội dung cần vẽ vào Display Queue; OLED Task là task duy nhất được chạm vào OLED.

Mutex (bảo vệ OLED, UART debug) là mở rộng dự kiến — xem mục 9, chưa nằm trong sơ đồ này.

8. Task Design#

UI Task#

Responsibilities:

  • Process button events
  • Translate each gesture into a command (CMD_NAVIGATE / CMD_CONFIRM)

Priority:

2

Notes:

UITask holds no state — it does not know the menu cursor or the machine state. Both belong to WashingManager (single owner), so the screen and the command interpretation can never disagree.

WashingManager Task#

Responsibilities:

  • State machine execution
  • Menu cursor ownership and the single source of every display update
  • System coordination
  • Motor control
  • Valve control

Priority:

3

Notes:

WashingManager is the owner of all machine states.

Sensor Task#

Responsibilities:

  • Monitor door sensor
  • Monitor water level sensor
  • Update event bits

Priority:

2

Period:

100 ms

OLED Task#

Responsibilities:

  • OLED rendering
  • Display system status

Priority:

1

Notes:

OLEDTask is the only task allowed to access the OLED driver.

10. Simulation Timing#

Fill Water:

Up to 10 seconds — a safety timeout only. The inlet valve stays open until the water level sensor reports full; if it never does, the machine enters ERROR

Wash:

20 seconds

Drain:

5 seconds

Spin:

10 seconds

These values are configurable and may be adjusted during development.

13. Design Rules#

  1. WashingManager owns all system states.
  2. OLEDTask owns all OLED access.
  3. Drivers must not depend on FreeRTOS.
  4. BSP hides HAL from application code.
  5. Keep ISR execution short.
  6. Use Queue for commands and messages.
  7. Use Event Groups for status synchronization.
  8. Use Task Notifications for lightweight wake-up events.
  9. Avoid blocking operations inside ISR.
  10. Explain FreeRTOS APIs before introducing them.
